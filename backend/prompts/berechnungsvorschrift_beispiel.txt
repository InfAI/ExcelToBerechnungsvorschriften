# Beispiele: Excel-Formel → Berechnungsvorschrift (JSON)

Format: BEISPIEL-EINGABE (Zelleneingabe) gefolgt von GEWÜNSCHTES JSON-OUTPUT.
Im Output: name (Platzhalter "N/A" – wird ignoriert, die Nutzer-Beschreibung wird als Name verwendet), formel, variablen, metadaten. Kein referenz_berechnungsvorschrift_id; jede Variable mit ist_primitive: true.
Jede Wertquelle (Zellreferenz oder Tabellenspalte, die Werte liefert) = eine Variable. formel nur mit Variablennamen aus variablen[] (exakt); keine werttragenden Begriffe ohne Variable.
Variablennamen im formel-String müssen exakt mit variablen[].name übereinstimmen.
Zellreferenzen: zellenidentifikator setzen (z.B. "D7", "A9"). Tabellenspalten: kein zellenidentifikator. Matching nutzt Tabellenidentifikator, Tabellenblatt und Zellenidentifikator.

---

BEISPIEL 1 – Einfache Formel, eine Variable

BEISPIEL-EINGABE:
Tabellenidentifikator: Tabelle1
Tabellenblatt: Sheet1
Zellenidentifikator: A1
Beschreibung: Monatliches Nettogehalt berechnen
Formel: =B1/12

GEWÜNSCHTES JSON-OUTPUT:
{
  "name": "N/A",
  "formel": "Jahresnettogehalt / 12",
  "variablen": [
    {
      "name": "Jahresnettogehalt",
      "ist_primitive": true,
      "zellenidentifikator": "B1"
    }
  ],
  "metadaten": {
    "kategorie": "Gehalt",
    "symbol": "MNG",
    "datentyp": "decimal",
    "einheit": "EUR"
  }
}

Erklärung: B1 wird aus der Beschreibung ("Nettogehalt") als "Jahresnettogehalt" interpretiert. Der Name "Jahresnettogehalt" erscheint exakt so in formel.

BEISPIEL 4 – IFERROR: nur Wert-Teil übernehmen

Fehlerbehandlungs-Funktionen (IFERROR, IFNA) nicht in den Pseudocode übernehmen. Nur den ersten Parameter (den eigentlichen Ausdruck) in Pseudocode umwandeln; Ersatzwert und Fehlerbehandlung weglassen.

  "name": "N/A",
  "formel": "Umsatz / Menge",
  "variablen": [
    {"name": "Umsatz", "ist_primitive": true, "zellenidentifikator": "A1"},
    {"name": "Menge", "ist_primitive": true, "zellenidentifikator": "B1"}
  ],
  "metadaten": {
    "kategorie": "Umsatz",
    "symbol": "UPE",
    "datentyp": "decimal",
    "einheit": "EUR/Stk"
  }
}

Erklärung: Nur A1/B1 wird umgewandelt → "Umsatz / Menge". Der Ersatzwert "-" und die Fehlerbehandlung von IFERROR erscheinen nicht im Pseudocode.

BEISPIEL 6 – IFERROR + SUMIFS/COUNTIFS, Tabellenbezüge als Wertquellen = Variablen

Formel nutzt IFERROR (nur Wert-Teil übernehmen), SUMIFS/COUNTIFS (bedingte Summe/Anzahl) und Tabellenbezüge.
Jede Wertquelle wird zu einer Variable: (1) Zellreferenz A9 → "Ausbildungsstand"; (2) Tabellenspalte MAJahr1[Arbeitsstunden/ Jahr] (Summenbereich) → "Arbeitsstunden_pro_Jahr". Im formel nur diese Variablennamen verwenden.

BEISPIEL-EINGABE:
Tabellenidentifikator: MAJahr1
Tabellenblatt: Sheet1
Zellenidentifikator: B10
Beschreibung: Durchschnittliche Arbeitsstunden pro Jahr nach Ausbildungsstand
Formel: =IFERROR(SUMIFS(MAJahr1[Arbeitsstunden/ Jahr],MAJahr1[Ausbildungsstand],A9)/COUNTIFS(MAJahr1[Ausbildungsstand],A9)," ")

GEWÜNSCHTES JSON-OUTPUT:
{
  "name": "N/A",
  "formel": "Summe(Arbeitsstunden_pro_Jahr, gefiltert nach Ausbildungsstand) / Anzahl(gefiltert nach Ausbildungsstand)",
  "variablen": [
    {"name": "Ausbildungsstand", "ist_primitive": true, "zellenidentifikator": "A9"},
    {"name": "Arbeitsstunden_pro_Jahr", "ist_primitive": true}
  ],
  "metadaten": {
    "kategorie": "Personal",
    "symbol": "DAPJ",
    "datentyp": "decimal",
    "einheit": "h"
  }
}

Erklärung: IFERROR wird weggelassen (nur der erste Parameter wird umgewandelt). A9 → Variable "Ausbildungsstand" mit zellenidentifikator: "A9"; Tabellenspalte MAJahr1[Arbeitsstunden/ Jahr] (Summenbereich) → Variable "Arbeitsstunden_pro_Jahr" ohne zellenidentifikator (keine Einzelzelle). Beide Variablennamen erscheinen exakt so in formel.

BEISPIEL 7 – INDEX + MATCH (Tabelle, Zeilen- und Spaltenkriterium)

INDEX(Tabelle, Zeile, Spalte) liefert den Wert an Position (Zeile, Spalte). MATCH liefert Zeile/Spalte aus Kriterien.
Wertquellen: (1) Tabelle Lohn[] → Variable "Lohn_Tabelle"; (2) Zelle H9 (Ausbildungsstand) → Variable "Ausbildungsstand"; (3) Zelle I4 (Spaltenkopf) → Variable "Spaltenkopf". Lohn[Ausbildungsstand] und Lohn[#headers] sind Lookup-Bereiche, keine zusätzlichen Variablen.
Für Auswertung mit echten Werten: operation = "index_lookup" setzen; Variablen-Reihenfolge zwingend: [Tabelle, Zeilenkriterium, Spaltenkriterium].

BEISPIEL-EINGABE:
Tabellenidentifikator: Lohn
Tabellenblatt: Sheet1
Zellenidentifikator: J10
Beschreibung: Lohnwert aus Tabelle Lohn für Ausbildungsstand und Spaltenkopf
Formel: =INDEX(Lohn[],MATCH(H9,Lohn[Ausbildungsstand],0),MATCH(I4,Lohn[#headers]))

GEWÜNSCHTES JSON-OUTPUT:
{
  "name": "N/A",
  "formel": "Wert aus Lohn_Tabelle an Zeile(Ausbildungsstand) und Spalte(Spaltenkopf)",
  "variablen": [
    {"name": "Lohn_Tabelle", "ist_primitive": true},
    {"name": "Ausbildungsstand", "ist_primitive": true, "zellenidentifikator": "H9"},
    {"name": "Spaltenkopf", "ist_primitive": true, "zellenidentifikator": "I4"}
  ],
  "operation": "index_lookup",
  "metadaten": {
    "kategorie": "Personal",
    "symbol": "LWT",
    "datentyp": "decimal",
    "einheit": "EUR"
  }
}

Erklärung: Lohn[] (Tabelle) → Variable "Lohn_Tabelle"; H9 → "Ausbildungsstand"; I4 → "Spaltenkopf". Reihenfolge der Variablen ist fest: (1) Tabelle, (2) Zeilenkriterium (H9), (3) Spaltenkriterium (I4) – für Auswertung mit echten Werten. operation = "index_lookup" kennzeichnet diese BV für 2D-Tabellenlookup. Alle drei Variablennamen erscheinen exakt in formel. Zellreferenzen H9 und I4 erhalten zellenidentifikator für Matching.

BEISPIEL 8 – IFERROR mit Division (D7/D8)

Zelle E8 berechnet D7/D8. Variablen stammen aus D7 und D8. Das Matching findet vorhandene Berechnungsvorschriften anhand von Tabellenidentifikator, Tabellenblatt und Zellenidentifikator (quelle).

BEISPIEL-EINGABE:
Tabellenidentifikator: Tabelle1
Tabellenblatt: Sheet1
Zellenidentifikator: E8
Beschreibung: Verhältnis berechnen
Formel: =IFERROR(D7/D8," ")

GEWÜNSCHTES JSON-OUTPUT:
{
  "name": "N/A",
  "formel": "Dividend / Divisor",
  "variablen": [
    {"name": "Dividend", "ist_primitive": true, "zellenidentifikator": "D7"},
    {"name": "Divisor", "ist_primitive": true, "zellenidentifikator": "D8"}
  ],
  "metadaten": {
    "kategorie": "Berechnung",
    "symbol": "VD",
    "datentyp": "decimal",
    "einheit": ""
  }
}

Erklärung: IFERROR wird weggelassen. D7 → Variable "Dividend" mit zellenidentifikator: "D7"; D8 → Variable "Divisor" mit zellenidentifikator: "D8". Matching: BVs mit gleichem Tabellenidentifikator, Tabellenblatt und Zellenidentifikator (D7/D8) werden verlinkt.

BEISPIEL 9 – Zellreferenz aus anderem Tabellenblatt (Cross-Sheet)

Formel referenziert Zelle G19 im Tabellenblatt "1. Lohn AW", die Formel steht aber in einem anderen Blatt.
Ohne tabellenblatt_referenz würde das Matching nur im Blatt der Formel suchen und die BV in "1. Lohn AW" nicht finden.

BEISPIEL-EINGABE:
Tabellenidentifikator: Tabelle1
Tabellenblatt: Übersicht
Zellenidentifikator: E10
Beschreibung: Lohnanteil als Prozentwert
Formel: =$'1. Lohn AW'.G19/100

GEWÜNSCHTES JSON-OUTPUT:
{
  "name": "N/A",
  "formel": "Lohnwert / 100",
  "variablen": [
    {
      "name": "Lohnwert",
      "ist_primitive": true,
      "zellenidentifikator": "G19",
      "tabellenblatt_referenz": "1. Lohn AW"
    }
  ],
  "metadaten": {
    "kategorie": "Personal",
    "symbol": "LAP",
    "datentyp": "decimal",
    "einheit": "%"
  }
}

Erklärung: G19 liegt in "1. Lohn AW", nicht im Formel-Blatt "Übersicht". tabellenblatt_referenz: "1. Lohn AW" ist zwingend, damit das Matching die passende BV findet.
